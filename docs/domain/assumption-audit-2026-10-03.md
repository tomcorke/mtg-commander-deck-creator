# MTG / Commander assumptions in the code

Audited on **2026-10-03**, against source commit `e7d6a1e0f189745a5a3cdbf3c0ba64b8318cbcb3`. Rechecked the signature implementation and its line references after the worktree was rebased onto this commit. Paths and line numbers are relative to the repository. I read `AGENTS.md`, `README.md`, `TODO.md`, and the existing agent, recommendation, eligibility, investigation, and Deck Doctor documentation before tracing `src/` and `scripts/`. No repository files were changed by this audit.

The rules reference is the **2026-09-25 Comprehensive Rules**, linked by Wizards' current [rules page][rules]. In particular, legendary Vehicles/qualifying Spacecraft and the newer partner variants below are current rules, not mistakes inferred from older Commander knowledge. Policy and provider observations are dated; they must not become permanent lists without an update procedure.

**Classes:** **Rule** = Comprehensive Rules / official format construction rule; **Policy** = Wizards format policy; **Provider** = a data-provider contract or observed response; **Heuristic** = community convention or an app-specific estimate. **Correct** does not mean a heuristic has been validated with players. **Incomplete** means a real rule or data case is missing. **Unverified** means primary-source evidence did not establish the claim.

## Follow-up implementation

The construction checks in `src/domain/commander-construction.ts` now cover start, import, search/manual add, recommendation Add decisions and guidance, basic-land additions, sideboard-to-deck moves, promotion, and review swaps/undo. New card snapshots retain Oracle identity and policy metadata. Front-face eligibility, Grist, basic and Oracle copy exceptions, all five partner ability families, and fail-closed metadata checks have regression coverage. Chosen-colour commanders are explicitly unsupported. Manual/import conversion now retains front-face mana costs.

The table preserves the original dated audit, not a description of every fixed path. A3 and I2 include A15 follow-up results. B12 in `TODO.md` tracks the remaining saved-deck/queue refresh and visible legality warnings. A15 and B13 cover the policy/provider and mana-analysis work.

## Gaps and errors to address first

1. **Use one construction-validation boundary.** Import, start, promotion, ordinary recommendations, swaps, and saved-deck load disagree on eligibility, identity, banned status, and duplicates. Some do no current legality check at all. A complete count must not be labeled proof of legality.
2. **Fix repeated-card rules.** Snow basics fail the exact `Basic Land` check; any-number and seven/nine-copy exceptions are absent; import admits unrestricted quantities. Handle interchangeable names independently of printing/display aliases.
3. **Represent designated commanders instead of parsing display names.** Imported pairs become one exact-name lookup; most pairing abilities are unsupported/unvalidated. Any-face eligibility wrongly admits Westvale Abbey and Elbrus. Preserve chosen-color commanders and distinguish Brawl from Commander.
4. **Retain authoritative identity data.** The legacy fallback includes extort reminder text and misses characteristic-defined/indicator colors; other callers substitute unknown identity with empty identity. Add separate companion designation/condition checks if companions are supported, including Lutri's current companion-only ban.
5. **Keep optional exclusions separate from official brackets.** Tutor restrictions were removed in 2025; precons no longer define Core. Upgraded is not “zero Game Changers.” No deck-wide budget, mass-land-denial, game-ending-combo, loop, or intent/timing evaluation exists. The current UI caveat should remain.
6. **Correct face/data semantics.** Manual/import conversion loses face mana costs; multi-face does not imply a back image; transform land backs are not opening land drops. Hybrid Phyrexian SVGs, `{C/color}` search, and `{P}` meaning need current symbology.
7. **Correct multiplayer simulation assumptions.** Draw on turn one; distinguish potential mana from available/payable output. Keep partial-deck and land-only results visibly qualified.
8. **Review provider drift.** Current EDHREC samples use `highliftcards`, leaving the old high-synergy mapping stale. `order=random` is not documented and the live samples were alphabetical. Script collection pacing is 100 ms versus the current 500 ms limit. The 15-minute cache is shorter than Scryfall's 24-hour recommendation.
9. **Document heuristic limits rather than sourcing them as rules.** Land/ramp/draw/removal/wipe regexes, source proxies, land formula, 70/85 thresholds, theme tags, six synergy rules, scores, and engine thresholds need examples and false-positive/negative cases. Missing detection does not mean a card is ineffective.

Verification included current Wizards/Scryfall/EDHREC pages and selected API responses. Direct dependency-free calls reproduced snow/unlimited-card rejection, reminder-text identity contamination, back-face commander acceptance, and generic-mana payment from a nonproducing land. ## Domain topics agents most need documented

1. **Construction model:** exactly 100 physical cards, designated commander(s), library/mainboard terminology, partial decks, planning sideboard versus official no-sideboard rules, companion outside the deck.
2. **Copy limits:** basic supertype including snow/Wastes; exact English/interchangeable names; any-number and bounded Oracle exceptions; quantity versus printing identity.
3. **Color identity:** authoritative Scryfall field, hybrid/Phyrexian/`{C}`/snow distinctions, reminder exclusion, indicators/CDAs, back/alternative faces, basic land types, chosen-color commanders.
4. **Eligibility and pairing:** front-face characteristics; current legendary Vehicles/Spacecraft rule; explicit permissions; Brawl distinction; every current partner variant and its compatibility requirements.
5. **Companions:** starting-deck conditions include commanders, outside-game identity/name restrictions, `{3}` special action, incompatible deck-size conditions, current companion-role bans.
6. **Format policy with dates:** authoritative ban sources, current Game Changers source, bracket intent/timing and counts, tutor-policy change, precon decoupling, Rule Zero; refresh/version procedure for saved snapshots.
7. **Mana semantics:** mana value versus cost/payment, split/fuse, MDFC, transform/meld, Adventure and newer alternative-characteristic layouts; generic versus colorless; potential versus available production.
8. **Scryfall contract:** Oracle/gameplay identity versus printing identity; nullable/missing fields; layouts/images; legality versus commander eligibility; Tagger versus Oracle queries; pagination, rank, release date, finishes/prices, symbology, current rate/cache requirements.
9. **EDHREC evidence:** public JSON is undocumented; page kinds/list taxonomy; inclusion denominators, synergy versus raw/log lift, deck counts/preview-date filtering, theme aliases, co-occurrence versus verified interaction, sampling bias.
10. **Guidance and its known limits:** role taxonomy and overlap, land allocation/formula, source/pip counts, commander availability, scoring/batching, signature engines, synergy versus infinite/game-ending combos and mass land denial.
11. **Simulation scope:** multiplayer opening draw, 99/98-card library versus partial snapshots, mulligans/land-drop rules, unsupported costs, conditional payability, confidence/sampling, and exclusions from a land-only model.
12. **Provider/import fixtures:** parseable versus legal decks, unsupported lines/sections, exact printing fallback, app export round-trip, dated Moxfield behavior, mutable Archidekt precon IDs, and what synthetic tests do not prove.

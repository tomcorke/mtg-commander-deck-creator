# A14: autosave design and browser handoff

## Storage and ownership

Each workspace writes only `commander-autosave:<workspace-id>`. The current id lives in `sessionStorage` under `commander-workspace`. Manual saves remain under `commander-saved-decks`; autosaving, migration, and retention never write that key.

A fresh tab restores the latest draft. If its source is inactive, the tab acquires that workspace's lock and resumes it, including its manual-save association. If the source is live, the tab allocates its own id but stores the copy only in session recovery until its first changed state or name. Reload before that edit does not create an origin autosave. A duplicated tab follows the same lazy-copy path when its inherited workspace is already owned. This keeps unedited tabs from adding identical drafts or displacing distinct drafts under the count limit. Migration leaves one origin draft, not a migrated draft plus startup copies.

Reload reuses the tab's workspace. Opening any draft explicitly from the picker makes a stored copy, whether its original is active or inactive. Live-source copies and picker copies lose their manual-save association, so editing them cannot silently overwrite the original named save. A taken manual-save name offers an explicit Overwrite action with confirmation. Starting a new deck or loading a manual save creates another workspace and retains the previous autosave subject to the configured limits.

Two changes from the coordinator's suggested mechanism address concrete races:

- **Web Locks own workspaces.** A BroadcastChannel ownership ping can miss a frozen tab, and two simultaneous duplicate startups can both time out before either answers. An exclusive, non-waiting Web Lock makes ownership atomic. BroadcastChannel is used only to refresh other tabs' draft lists; storage events and focus provide additional refresh paths. Cleanup must acquire the candidate's lock before deleting it, so a stale presence list cannot authorize deletion. No liveness timeout is used.
- **Session recovery covers reload handover.** Reload releases the old page's lock before the new page claims it. Another tab could prune that temporarily inactive autosave in between. One validated recovery copy in `commander-workspace-recovery` survives that gap and restores the tab's own deck, not the origin's latest deck. A new empty workspace clears that copy. A cached page reloads on `pageshow` before it can write again.

Without Web Locks, every page load forks into a fresh id and cleanup and draft deletion are disabled. The picker explains that cleanup is unavailable; writes are never shared. Failed storage writes display a fixed, styled export alert without moving page content. A quota error triggers a locked cleanup-and-retry pass: it removes only inactive drafts beyond the configured count or age limits, stopping when the pending write fits. A new pending draft counts towards the maximum. Drafts within both limits, live workspaces, the writing workspace, manual saves, and unrelated storage keys are never removed. If no eligible deletion frees enough space, the export alert remains. A dismissible alert reports any cleanup deletions, including when the retry still fails. Non-quota failures do not authorize this cleanup. Saves are serialized so an older quota retry cannot overwrite a later edit.

Autosaves, session recovery, and manual saves use the same queue field table and value rows instead of repeating object keys for every card. Queued and deferred cards retain only their selected printing, with its index reset to zero; their scalar card details, scoring inputs, finish, and manual-selection flag remain intact. Deck, sideboard, and commander printing lists are unchanged. The existing printing-enrichment path fetches alternatives from `printsUri` for the visible batch and its preview after restoration, preserving the selected image and finish. Later batches fetch alternatives when shown. Full-object saves and the earlier compact queues with full printing lists remain readable. Fetching alternatives alone does not mark a manual save as modified or advance an autosave's timestamp. Legacy migration writes and validates its replacement before removing `commander-deck-state`; a failed migration retains and restores the legacy deck.

Retention defaults to 10 drafts and seven days. Limits are shared across tabs and apply at startup, after new or changed autosaves, and when applied in the picker. Live workspaces can exceed both limits. Applying limits previews the eligible deletion count and asks for confirmation before deleting drafts; the result shows the actual count removed. Individual inactive drafts have a two-click Delete action backed by an atomic lock check. A failed lock or changed-draft check shows “Draft is in use or changed; try again.” Storage-full failures when saving limits identify the quota problem rather than suggesting invalid input. The picker lists drafts separately from manual saves, with commander previews, card counts, relative saved times, and exact timestamp tooltips. Unchanged reloads do not advance the saved time. The restored-draft notice appears once for each workspace in a tab session, rather than on every reload; a duplicate with a new id still gets its copy notice.

## Automated gate

`src/autosaves.test.ts` uses independent session stores, shared origin storage, an atomic Web Locks stub, and BroadcastChannel stubs. Its go/no-go check passed before retention was added. Tests cover concurrent edits and reloads, simultaneous duplicate startup, active and inactive draft copies, migration and failed writes, retention boundaries, suspended owners, reload/prune handover, manual-save separation, picker notifications, and recovery after a previous recommendation error. Follow-up tests cover retention-bound quota cleanup and rapid-edit retries, cleanup notices after successful and failed retries, storage-full limit failures, compact queue round trips, printing enrichment and switching after restoration, unchanged startup and reload without copies, a single migrated draft, inactive-source manual-save links, explicit named-save overwrites, protected draft deletion and failure status, deletion-count previews, and notice suppression after reload. A synthetic printing-heavy fixture with 12 deck cards, 19 queued cards with 40 printing options each, and one deferred card must serialize below 60,000 characters for each save type. It currently uses 54,341 characters for the autosave and session recovery, and 54,335 for the manual save. This is a fixture budget, not a maximum for every possible deck.

Opus reported that isolation, duplicate-tab forking, live-draft copies, restored notices, migration recovery, Back/Forward cache, and picker keyboard handling passed in Chrome. Pi did not run interactive browser checks or verify rendered appearance. The follow-up Chrome checks below remain required before merge.

Existing out-of-scope boundary: the commander-printing effect does not cancel its foreground requests when decks change. This branch disables picker deck opens during recommendation loading but does not add general foreground-request cancellation.

## Follow-up Chrome checks

Use a disposable profile and an unused port in 5200–5299.

1. In DevTools Application > Local Storage, measure an edited autosave and a manual save made from the same deck. Queued and deferred cards should store one selected printing, not full lists. Reload each save type: verify queue order, Add/Later/Ignore choices, preferences, deferred cards, and selected images and finishes. Printing controls should return when alternatives load and still switch art and finish. Repeat with a manually selected foil printing and by reopening the same manual save without reloading the page. Older full-object autosaves and manual saves must still open.
2. Keep two different drafts live and create inactive drafts plus a manual save. Fill unrelated localStorage keys until an edit causes a quota error. Only inactive drafts exceeding the count or age limit may be removed; check the deletion alert. If cleanup frees enough space, the latest edit should save and survive reload. Live drafts, manual saves, junk keys, and inactive drafts within both limits must remain unchanged. Repeat rapid edits during cleanup. When no eligible deletion frees enough space, the export alert should appear without moving content; any completed deletions must still be reported. Freeing space and editing again should clear the export warning.
3. Open three fresh or duplicated tabs without editing. Verify no additional origin drafts appear, including after reloading the unedited copies. Edit one copy: exactly one new draft should appear, and other tabs must retain their decks. Repeat with a low maximum so unchanged tabs cannot evict distinct drafts.
4. Seed a legacy deck linked to a named manual save and open two tabs together. Verify exactly one origin draft after migration. Close the owner and restore in a fresh tab: the manual-save link and name must survive, an edited deck must show the `*` marker, and saving must overwrite the same manual-save id. A live-source copy must stay unlinked. Enter its existing save name: Overwrite must be offered; cancelling must leave the save unchanged, and confirming must replace that save without creating another id.
5. Apply limits that would delete inactive drafts. Check the confirmation count, cancellation without storage changes, and the actual deletion count after applying. Fill storage and try saving different limits: the error should say storage is full, not “Use a count…”. Delete an individual inactive draft using its confirmation action. Hold its Web Lock or change its stored record between confirmation clicks: deletion must fail with “Draft is in use or changed; try again.” Current and other live drafts must have disabled Delete controls and survive all cleanup. Manual-save and draft card counts should have matching text sizes.
6. Verify the recovery notice appears once per tab workspace, survives dismissal through recovery data, and stays hidden on reload. A newly duplicated workspace must still identify its own copy. Check rows do not repeat an identical deck and commander name. Review alerts and picker controls in light, dark, commander-themed, and narrow layouts; verify thumbnail hover/focus previews, card details, focus trapping, Escape, and focus return after the new confirmation actions.

## Original Opus browser scenarios

Use an unused port in 5200–5299. Use a disposable browser profile or back up existing storage before migration and retention tests.

1. Build deck A and add cards. Open a fresh tab B at the same origin. Check B's notice names the automatically restored commander, card count, and saved time, and offers both another draft and a new deck before editing. Verify notice dismissal does not remove recovery data.
2. In B, start a different deck and make different additions/decisions. Alternate edits between A and B. Reload both tabs, including simultaneous reloads. Each must recover its own commander, main deck, sideboard, and recommendation choices. Check session ids differ and each tab updates only its own autosave key.
3. Use the browser's Duplicate tab command on A. Verify the duplicate says it edits its own copy and receives a new id. Edit both copies and reload them. Repeat while A is hidden, and with a browser-frozen original if available. Neither may overwrite the other.
4. In B's picker, open A's active draft. Confirm the active label explains copying, the new copy edits independently, and B's previous deck remains listed. Close A and open its inactive draft; this must also make a copy rather than reuse A's key.
5. Create a named manual save. Confirm manual saves have their own section and explicit overwrite/delete controls. Auto-edit, copy, start a new deck, apply retention, and reload. None of those operations may change the manual-save record. Loading a manual save must create a workspace without erasing the prior draft.
6. With A and B live, set the maximum to one. Both live recovery points must remain, even if older than the age limit. Create several inactive drafts, close their owners, then apply limits or edit a live deck. Eligible oldest/expired drafts should disappear; live drafts and manual saves must remain. Confirm the settings survive reload and appear in the other tab.
7. Exercise reload handover with the maximum at one: release a tab's workspace, let another tab prune its origin record, then reload the original tab with its session storage intact. The session recovery point must restore its own deck and recreate its autosave, not load the other tab's deck.
8. Seed a valid legacy `commander-deck-state` record and load two tabs together. Verify one migrated recovery entry, distinct working copies, and deletion of the legacy key only after the migrated entry exists. Repeat with writes denied/quota exhausted: the legacy recovery must survive and an export warning must appear.
9. Check the notice and picker in light, dark, commander-themed, and narrow layouts. Tab/Shift+Tab must stay inside the picker, Escape/backdrop/close must dismiss it, and focus must return to the opener. Commander thumbnails must enlarge from hover/focus and open card details, including when the picker is opened from the start screen. The current draft's Open action must also work from the start screen. Check number-input labels, limits, validation, and saved-time tooltips.
10. Navigate away and back, including browser Back/Forward cache restoration. Ownership must be reacquired before edits. Disable Web Locks in a disposable test context: duplicate/reload must fork safely, and cleanup must remain disabled with an explanation.
